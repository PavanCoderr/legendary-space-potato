Build a functional web application called **QubitVerse**.

QubitVerse is an **AI-Based Interactive Quantum Algorithm Learning Platform**.

The objective is to create one integrated platform where users can learn quantum computing concepts, build quantum circuits, simulate them, visualize quantum states, receive contextual AI guidance, practice problems, and track their progress.

Do not treat this as a static landing page or design prototype.

Build the actual application with working interactions, state management, calculations, and navigation.

---

## CORE PRODUCT FLOW

Implement this complete learning flow:

**Choose Lesson**
→ **Learn Concept**
→ **Interactive Exercise**
→ **Build Circuit**
→ **Run Simulation**
→ **Visualize Quantum State**
→ **Ask AI**
→ **Complete Challenge**
→ **Update Progress**

This unified flow is the main purpose of QubitVerse.

# 6. QUANTUM SIMULATION

Implement a lightweight quantum simulator.

Do not fake simulation results.

The simulator should calculate results based on the circuit.

At minimum support:

* Single-qubit states
* Multi-qubit states
* H
* X
* Y
* Z
* CNOT
* Measurement

Allow configurable measurement shots.

Example:

```text
Shots: 1000

|0⟩ : 502
|1⟩ : 498
```

Results may naturally vary because of measurement randomness.

The same circuit must produce corresponding results everywhere in the application.

For example:

Circuit Builder
↓
Simulator
↓
Probability results
↓
Bloch Sphere
↓
AI Tutor

All should use the same circuit/state information.

---

# 7. QUANTUM STATE VISUALIZATION

Implement quantum-state visualization.

For single qubits, provide a Bloch Sphere representation.

The Bloch Sphere should update when gates are applied.

Example:

```text
|0⟩
 ↓
H
 ↓
Superposition
```

When possible, animate the state transition.

Display:

* Current state
* Applied gate
* State vector
* Probabilities

The Bloch Sphere is one of QubitVerse's key differentiating features.

---

# 8. SIMULATOR RESULTS

After running a circuit, show:

### Circuit

The executed circuit.

### Quantum State

Current state representation.

### Probabilities

Probability of measurement states.

### Measurement Results

Number of occurrences for each state.

Example:

```text
1000 shots

|00⟩  49.8%
|11⟩  50.2%
```

For Bell-state circuits, the simulator should produce correlated results.

Do not hard-code these numbers.

# 9. CODE MODE

Support two ways of creating circuits:

**Visual Circuit**

and

**Quantum Code**

Implement a code editor for quantum circuits.

Example:

```python
qc = QuantumCircuit(2)

qc.h(0)
qc.cx(0, 1)

qc.measure_all()
```

The application should maintain a relationship between the code representation and circuit representation where practical.

If full bidirectional conversion is too complex for the first implementation, prioritize visual circuit → simulator and provide code execution as a separate mode.

# 10. AI QUANTUM TUTOR

Implement a contextual AI tutor.

This must not behave like a generic chatbot.

The tutor should understand the current application context.

Provide context such as:

* Current lesson
* Current circuit
* Selected gate
* Quantum state
* Simulation result
* User error
* Current challenge

Supported actions:

* Explain this
* Why did this happen?
* Find my mistake
* Give me a hint
* Explain my circuit
* Explain the result
* Improve my code

Example:

User:

"Why did the H gate give approximately 50/50?"

Tutor:

"The Hadamard gate transforms |0⟩ into an equal superposition of |0⟩ and |1⟩. When measured, both outcomes therefore have approximately equal probability."

If no external LLM API is available, create a contextual local/mock AI service with predefined responses.

The application must still work without an API key.

Keep the AI layer modular so a real LLM can be connected later.
