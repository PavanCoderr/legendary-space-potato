# Design Doc: E4 — Backend-Served Lessons with Zero UI Changes

Author: Buffy · 2026-09-18 · Status: **Ready for Claude to implement**
Companion to: `.agent/plan/plan_for_claude.md` (E4) ·
`.agent/report/2026-09-18-learning-content-review.md` (finding F3)

## 0. Goal

`GET /api/lessons` returns the complete curriculum — including YouTube video ids
(spec §2: "YouTube IDs must be stored as editable backend data") — and the frontend
consumes it **without touching any UI file**.

Hard constraints:

1. **No UI redesign/rewrite** (CLAUDE.md critical rule): no component, page, routing,
   or styling changes.
2. **Never break the app**: any backend lesson failure falls back to the bundled
   curriculum — the same pattern every other endpoint in `services/api.ts` already uses.

> **Deviation from the plan's "single-file change" note, deliberately:** pages import
> the module constant `LESSONS` directly (~17 sites), so redirecting them through state
> would require touching every page. The only zero-UI lever is making the data module
> itself replaceable at bootstrap. Total frontend footprint: 2 small, non-visual files
> (`services/api.ts`, `src/data/lessons.ts` + 3 lines in `main.tsx`). The spirit of the
> rule — no visual/UX change — is fully preserved.

## 1. Current state (evidence)

- `backend/src/db/seed.ts` (~line 91) writes rich JSON (summary, objectives,
  prerequisites, xp, video, visualization, aiPrompts, interactive, example, quizIds,
  challengeId, nextLessonId, icon) into `lessons.description`. **Not** included:
  `concept` (it's seeded into the separate `concepts` table) and `minutes` (stored only
  as the `duration` column string).
- `backend/src/lessons/routes.ts` `GET /` returns the thin table rows raw; the rich
  JSON is never unpacked.
- `services/api.ts:307-318` — `fetchLessons()` already exists: GETs `/api/lessons`,
  validates, falls back to bundled `LESSONS` on any failure. Nobody calls it.
- Pages render `<lesson.icon size={…}/>` — the frontend `Lesson.icon` must be a
  **LucideIcon component**; the backend sends the icon *name string* (seed stores
  `icon.displayName ?? icon.name` → `CircleDot`, `Waves`, `Link2`, `Blocks`, `Sigma`).
- `Lesson.example.circuit` / `interactive.startCircuit` are `QuantumCircuit` runtime
  objects in the frontend; the backend stores serialized form. `deserializeCircuit` is
  the existing rebuild path (used exactly this way in `src/data/projects.ts:17`).

## 2. Backend change — `backend/src/lessons/routes.ts` (+ one seed line)

### 2.1 Seed: include the concept block in the description JSON

In `backend/src/db/seed.ts`, add `concept: lesson.concept,` to the JSON.stringify object
in the `UPDATE lessons SET description = ?` call. `INSERT OR REPLACE` reseeds on next
backend start — no migration needed.

### 2.2 Route: unpack and merge

```ts
interface LessonMeta {
  summary?: string; objectives?: string[]; prerequisites?: string[]; xp?: number;
  concept?: unknown; video?: unknown; visualization?: unknown; aiPrompts?: unknown;
  interactive?: unknown; example?: unknown; quizIds?: string[];
  challengeId?: string; nextLessonId?: string | null; icon?: string;
}

function unpackLesson(row: any): any {
  let meta: LessonMeta = {};
  try {
    meta = typeof row.description === 'string' && row.description.startsWith('{')
      ? JSON.parse(row.description) : {};
  } catch { meta = {}; } // topic rows seeded with plain-string descriptions pass through
  return { ...row, ...meta };
}
```

- `GET /` → `res.json(lessons.map(unpackLesson))`
- `GET /:id` → same unpacking on the lesson row; keep the existing
  `{ lesson: { ...lesson, concepts }, progress }` envelope unchanged.

### 2.3 Resulting payload per lesson

Table columns (`id`, `title`, `category`→topic, `duration`→minutes, `difficulty`→level,
`order`) merged (spread later wins) with the unpacked JSON: `summary`, `objectives`,
`prerequisites`, `xp`, `concept`, `video` (with `youtubeId`), `outline`, `interactive`,
`example`, `visualization`, `aiPrompts`, `quizIds`, `challengeId`, `nextLessonId`,
`icon` (string). Keep `description` (raw string) — harmless, frontend whitelists fields.

## 3. Frontend change

### 3.1 `src/services/api.ts` — normalize the HTTP payload

Add imports:

```ts
import type { LucideIcon } from 'lucide-react';
import { Blocks, CircleDot, CircleHelp, Link2, Sigma, Waves } from 'lucide-react';
import { deserializeCircuit, type SerializedCircuit } from '../quantum/circuit';
```

Icon registry (C1 fix) — the five names the seed produces, plus a safe fallback:

```ts
const LESSON_ICONS: Record<string, LucideIcon> = { CircleDot, Waves, Link2, Blocks, Sigma };
const ICON_FALLBACK: LucideIcon = CircleHelp;
```

Normalization with the **integrity rule** (validate all-or-nothing per lesson — never
mix half HTTP / half bundled data):

```ts
function toFrontendLesson(http: any, fallback: Lesson): Lesson | null {
  // Required fields — reject the lesson entirely if any is missing/invalid
  if (!http || typeof http.id !== 'string' || typeof http.title !== 'string') return null;
  if (!http.video || typeof http.video.youtubeId !== 'string') return null;

  // C2: rebuild runtime circuits; failure → whole lesson rejected (falls back to bundled)
  let example: Lesson['example'];
  if (http.example?.circuit) {
    try {
      const parsed = deserializeCircuit(http.example.circuit as SerializedCircuit, http.title);
      example = { ...http.example, circuit: parsed.circuit };
    } catch { return null; }
  }

  const icon = (http.icon && LESSON_ICONS[http.icon]) || ICON_FALLBACK;

  return {
    ...fallback,                    // fills any field the backend didn't send (locked, outline shape, etc.)
    ...http,                        // backend values win
    id: http.id,
    title: http.title,
    topic: http.category ?? fallback.topic,
    level: http.difficulty ?? fallback.level,
    minutes: Number(http.duration ?? fallback.minutes) || fallback.minutes,
    xp: typeof http.xp === 'number' ? http.xp : fallback.xp,
    icon,                           // C1: string → component
    locked: false,
    example: example ?? fallback.example,
    video: http.video,
  } as Lesson;
}

function toFrontendLessons(payload: any[]): Lesson[] {
  const bundled = LESSON_MAP; // existing map, imported already? (see 3.3 note)
  const out: Lesson[] = [];
  for (const http of payload) {
    const fb = bundled[http?.id];
    if (!fb) continue;                              // unknown lesson id → skip (stale backend?)
    const lesson = toFrontendLesson(http, fb);
    if (lesson) out.push(lesson);                   // per-lesson integrity fallback
  }
  return out.length > 0 ? out : Array.from(Object.values(bundled));
}
```

Rewrite `fetchLessons()` (currently lines 307-318) to run the payload through
`toFrontendLessons()` before returning; keep the existing try/catch fallback and the
"empty array → local" check.

### 3.2 `src/data/lessons.ts` — make the module replaceable (~10 lines, additive)

The exported constants stay exported (all ~17 import sites keep working, same
references). Add an in-place replacement helper:

```ts
/** Runtime-replace the curriculum (E4). Mutates in place so all importers see it. */
export function replaceLessons(lessons: Lesson[]): void {
  LESSONS.length = 0;
  LESSONS.push(...lessons);
  for (const k of Object.keys(LESSON_MAP)) delete LESSON_MAP[k];
  Object.assign(LESSON_MAP, lessons.reduce((acc, l) => ({ ...acc, [l.id]: l }), {}));
  totalLessonXp = lessons.reduce((sum, l) => sum + l.xp, 0);
}
```

One-line companion change: `export const TOTAL_LESSON_XP = …` →
`export let TOTAL_LESSON_XP = …; let totalLessonXp = TOTAL_LESSON_XP;`
ES module live bindings make the updated value visible to all importers. Do NOT change
any lesson content in this file — the bundled array remains the fallback source of
truth. (`getLesson`, `firstLesson`, `recommendedLesson` already read the map/array
dynamically — no change.)

### 3.3 `src/main.tsx` — 3-line bootstrap, before first render

```ts
if (import.meta.env.VITE_API_BASE_URL) {
  try {
    const lessons = await Promise.race([
      api.fetchLessons(),
      new Promise<Lesson[]>(resolve => setTimeout(() => resolve(LESSONS), 1500)),
    ]);
    replaceLessons(lessons);
  } catch { /* bundled curriculum stays */ }
}
```

Must complete **before** `render` (wrap the existing render in the async flow) — React
reads the array during render, so mutating after first paint would leave stale UI until
navigation. Import `api` from `./services/api` and `replaceLessons, LESSONS` from
`./data/lessons`. No UI change.

## 4. Acceptance tests

**Backend** (extend `backend/test/progress.test.ts` or new `lessons.test.ts`):
- `GET /api/lessons` (with token): array of 5; `qubits` entry has string
  `video.youtubeId`, array `objectives`, string `icon`, object `example.circuit`,
  number `xp`, object `concept` (after seed change + reseed).
- `GET /api/lessons/qubits`: envelope `{ lesson, progress }` preserved; lesson carries
  the same unpacked fields.

**Frontend** (vitest, no `VITE_API_BASE_URL` in tests → bootstrap no-ops, existing
`app.test.tsx` unaffected):
- Unit-test `toFrontendLessons`: rich payload → icon is a function component, example
  circuit is a runtime `QuantumCircuit` (has `ops`); payload with missing
  `video.youtubeId` for one lesson → that lesson falls back to bundled; unknown id
  skipped; empty/invalid payload → bundled list.
- Typecheck must pass (`npm run typecheck`) — the `as Lesson` casts are contained in
  the normalizer.

**Manual end-to-end (the spec §2 proof):**
1. Run backend (8080) + frontend with `VITE_API_BASE_URL=http://localhost:8080`.
2. Change the `video.youtubeId` (or any content) in `backend/src/data/lessons.ts` only.
3. Restart backend (reseeds), reload the app → the Watch stage shows the new video.
   **Zero frontend edits.** That is the acceptance demonstration.

## 5. Rollback & failure modes

| Failure | Behaviour |
|---|---|
| Backend down / 500 / slow (>1.5 s) | bundled curriculum (bootstrap race or fetch catch) |
| One malformed lesson in payload | that lesson falls back to bundled (integrity rule) |
| Backend sends unknown lesson id | skipped |
| Need full rollback | unset `VITE_API_BASE_URL` — zero code changes |

## 6. Explicitly out of scope for E4

- Quizzes/challenges/glossary serving (E5/E6), auth flow changes (A5), any UI/styling.
- `interactive.startCircuit` runtime rebuild is NOT needed for this swap — verify with a
  grep whether any lesson-page component consumes `interactive.startCircuit` directly;
  if it does, rebuild it with the same `deserializeCircuit` call inside
  `toFrontendLesson` (one extra line, same pattern).
