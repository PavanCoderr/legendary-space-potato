### 2.3 ❌ P0 — the swap never happens (the curriculum is never installed)
Claude's claim: "main.tsx unchanged (bootstrap already existed)". **That is not
true — no bootstrap exists anywhere.** Evidence:

1. `src/main.tsx` (read in full, 23 lines): renders `<StoreProvider><App /></StoreProvider>`
   only — no `fetchLessons`, no `replaceLessons`, no async bootstrap.
2. `src/services/api.ts` (read in full, 504 lines): `replaceLessons` is *never
   imported or called*; `fetchLessons()` is *defined* (local + http variants) but
   has **zero callers** outside the file.
3. `src/state/StoreProvider.tsx` (read in full): no `fetchLessons`/`replaceLessons`
   anywhere; `loadInitialState()` (`state/persistence.ts`) reads only localStorage —
   it never touches the API.
4. Pages import the bundled array directly (`Dashboard.tsx`, `Learn.tsx`:
   `import { LESSONS } from '../data/lessons'`) — so they render whatever
   `LESSONS` holds at module load.
5. Project-wide search for `fetchLessons|replaceLessons` in `src/`: all 6 hits are
   inside `services/api.ts` itself.

**Consequence:** in HTTP mode (`VITE_API_BASE_URL` set), the app never requests
`GET /api/lessons`, so all backend-served lesson content (E4's entire purpose —
editable backend data per spec §2) is dead code. The feature works only in the
unit tests. The normalizer is correct but unreachable. Also note
`recommendedLesson()`/`getLesson()` etc. read `LESSONS`/`LESSON_MAP` at call time,
so `replaceLessons` at startup WOULD propagate — the mechanism was built correctly,
it is just never triggered.

**Required fix (E4b) — pick ONE, ≤6 lines each, no UI changes:**
- **(b1) main.tsx bootstrap (the plan's original 3-line option):** before
  `createRoot(...).render(...)`, fire
  `void Promise.race([api.fetchLessons().then(replaceLessons), timeout(1500)])`.
  Because all pages read `LESSONS` during render, lessons fetched after mount
  appear on the next render (React will re-render when the root re-renders; if the
  app needs an explicit tick, dispatch any state touch or call `replaceLessons`
  before render when the promise resolves fast enough — simplest correct form:
  await the race *before* `render()` with the 1.5 s timeout, so first paint
  already shows backend lessons and a downed backend costs ≤1.5 s).
- **(b2) api.ts lazy-install (alternative):** inside http `fetchLessons()` — but it
  has no callers, so this alone changes nothing; (b1) is the honest fix.

Claude: implement (b1), paste the ≤3-line diff in the progress log, and add one
unit test asserting `replaceLessons` is invoked on bootstrap (or test
`main.tsx`'s helper if extracted). Until then E4 stays `[~]`.
